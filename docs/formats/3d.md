# .3D models

XnGine v2.x polygon models, the same family as Daggerfall's ARCH3D. Props
in `MDMDOBJS.BSA`, enemies and avatars in `MDMDENMS.BSA`. The engine uses
the file in place: struct offsets equal file offsets.

Godot port: `scripts/loaders/mesh_3d.gd`.

DOS: (v1.00) loader `FUN_0013425d`, face iterator `FUN_0014ff0e`, entity
render `FUN_00150284`.

## Header

| Offset | Size | Type | Meaning |
|---|---|---|---|
| 0x00 | 4 | char[4] | version `v2.1` .. `v2.7` |
| 0x04 | 4 | u32 | vertex count (per frame) |
| 0x08 | 4 | u32 | face count |
| 0x0C | 4 | | UNCERTAIN |
| 0x10 | 4 | u32 | frame count (0 = static) |
| 0x14 | 4 | u32 | frame table offset |
| 0x18..0x2F | | | UNCERTAIN |
| 0x30 | 4 | u32 | vertex block offset (see below) |
| 0x34 | 4 | u32 | normal list offset: one s32 x, y, z per face (in static models it starts right after the vertex block) |
| 0x38 | 4 | | UNCERTAIN |
| 0x3C | 4 | u32 | face array offset |

### Frame table

`frame_count` entries of 16 bytes: `{u32 vertex_off, u32 uv_off,
u32 aux_off, u16, u16 pad?}`. Only `vertex_off` is used by the port; read
the offsets as **int32** (a negative or out-of-file offset rejects the
model, as the Godot port does). Frames are **not** guaranteed contiguous.

Four shipped models are rejected by both the Godot port and
`SkyNet.Formats.Model3D`: CHASSIS, EXPLOBIG and RUBBRFL (frame count set,
frame table all zeros) and DEADHEAD (the normals list sits between 0x30's
vertex block and the faces, so the packed-frame rule finds no whole
frame).

The word at 0x30 is a cursor the authoring tool left at whatever frame was
current when the file was saved; it is not always frame 0. When a frame
table exists, ignore 0x30. When there is none, vertices start at 0x30
and frames (if several) are packed back to back up to the face array.

Faces and UVs are shared by all frames; only vertex positions change. The
initial frame is 0.

## Vertices

`s32 x, s32 y, s32 z`, 12-byte stride. Units are **1/256 world unit**.
DOS axes (Y down). Godot conversion: `(x, -y, -z) / 256`, a rotation, so
the winding is preserved.

## Faces

Variable length; stride = `8 + 8 · vertex_count`.

| Offset | Size | Type | Meaning |
|---|---|---|---|
| +0 | 1 | u8 | vertex count |
| +1 | 1 | u8 | UNCERTAIN; **not** always 0 (non-zero on 1,394 faces of the shipped models) |
| +2 | 2 | u16 | texture type: bank = `>> 7`, record = `& 0x7F`; ≤ 0xFF = flat palette colour |
| +4 | 4 | u32 | UNCERTAIN; **not** always 0 (non-zero on 24,658 faces) |
| +8 | 8·n | | per vertex: `u32 vertex_ref, s16 du, s16 dv` |

`vertex_ref` to index:

| Version | Index |
|---|---|
| v2.6, v2.7 | `vertex_ref / 12` (byte offset) |
| v2.1 .. v2.5 | `vertex_ref / 4` |

Legacy v2.1/v2.5 models: ENDOSKEL, TORTURE, ENDORFL, T-REXHED, T-REXLEG.

**Read exactly `face_count` faces and always advance by the real stride.**
The vertex count is a u8 with no upper bound; large floor and ceiling
polygons have more than 8 vertices. Skip a bad face, never stop.

Some models omit faces that are never seen (bottoms, backs); that is
authentic.

### UVs

Units are 1/16 texel: `u = value / (16 · texture_width)`,
`v = value / (16 · texture_height)`.

- Point 0: absolute (du, dv).
- Point 1 = point 0 + delta; point 2 = point 1 + delta.
- Points 3..n: stored values are ignored. Extend the affine map defined by
  points 0-2 to the other (coplanar) vertices with barycentric
  coordinates.

Daggerfall's UV wrap (folding values beyond ±14336 by 8192) must **not**
be applied: SkyNET stores plain s16 deltas, and a 1024-unit edge
legitimately carries 16384.

## Winding and culling

The engine culls back faces. A face is visible from the side where its
vertices run **counter-clockwise**: outward normal = `(b − a) × (c − a)`,
the same in DOS and Godot axes. Evidence: SKY_SKY.3D (seen from inside)
has all faces wound that way; two-sided plates are stored twice with
reversed order; the stored face normals at 0x34 agree in direction with
the winding normal on 70,531 of 71,010 faces checked across every model
(the rest are degenerate or near-degenerate polygons).

Godot's front faces are clockwise, so the port emits fans as
`(0, k+1, k)` with back-face culling on. Drawing both sides makes the
reversed duplicates z-fight. Collision should still be two-sided, because
models omit unseen faces.

## Rotation

Instances are rotated by the MAP entity's pitch/yaw/roll
([map.md](map.md#variant-1-mesh-sub-record-23-bytes)).
